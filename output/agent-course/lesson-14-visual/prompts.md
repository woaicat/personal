## 第一张：设计原则与信任模式

```text
首屏标题“第 14 课  前端 UI 和人机协作”，副标题“我们不再设计工具，而是设计关系”，元信息“预计 30 分钟 · 系列：从 0 到 1 设计一个 Agent”。
本课要点：把自主性设计成可理解、可控制、可恢复的协作关系；用行动前、中、后的界面模式建立信任；让透明度与风险匹配，而不是展示所有过程。

用对照图呈现：传统软件“用户意图 → 点击/输入 → 系统响应”；Agent 系统“用户意图 → 制定计划 → 选择工具 → 自主行动 → 反馈与接管”。

第 1 节“设计原则”：五项原则为意图清晰、透明赋能、用户控制、反馈安全、协作而非替代；中心结论“可见性 + 可预测性 + 可控性 = 信任”。

第 2 节“设计模式：控制、同意与问责”：
行动前：意图预览、自主性调节；
行动中：可解释理由、置信度信号；
行动后：行动审计与撤销、升级路径。
展示“您的行程中断处理方案”意图预览卡，四步为取消原航班并退款、改签下午 2:30 直飞航班、更新酒店到店时间、发送新行程；按钮为“按此计划执行 / 编辑计划 / 我自己处理”。
展示四档自主性：“观察并建议 → 计划并提议 → 确认后行动 → 自主行动”，高亮“确认后行动”。
增加六模式摘要、道歉三步“承认错误 → 说明即时纠正 → 提供人工支持”，以及三阶段路线“基础安全 → 校准自主 → 主动委托”。

右侧大纲：1 设计原则；2 设计模式；3 识别透明性时刻；4 透明性的界面模式；5 模态与用户意图。继续学习指向“下一课：建立可观测性”。
```

## 第二张：透明性时刻与界面模式

```text
中段不重复课程标题与本课要点，从第 3 节开始。

第 3 节“识别必要的透明性时刻”：先用三栏对照“黑箱 / 必要透明 / 日志流水账”，结论为“先审计系统的决策逻辑，再决定界面在哪里开口”。

3.1 决策节点审计：三阶段八步。
准备与绘图：组建跨职能团队、画出端到端流程；
定位隐藏逻辑：标记模糊点、识别最佳猜测、弄清判断依据；
创造用户体验：写清晰解释、更新界面、验证信任。
保险理赔示例状态：评估损伤照片、审查事故报告、核实保单覆盖。

3.2 影响/风险矩阵：低影响+可逆为自动执行与被动提示；低影响+不可逆为确认与简单撤销；高影响+可逆为审阅与审阅轨迹；高影响+不可逆为意图预览与明确授权。

3.3 “等等，为什么？”测试：从“正在检查您的日历”引出“它在查谁的日历？”，改进为“检查您的可用时间 → 与医生排班同步 → 锁定预约时间”。

第 4 节“透明性的实用界面模式”：
状态公式“动词 + 具体对象 + 边界规则”；弱文案“正在搜索航班……”对比强文案“正在扫描机票价格，寻找 600 元以下的选项”。
四种界面容器：动态面包屑、动态清单、思考开关、审计轨迹。
失败处理：部分成功要显示成功与失败的具体项；工具故障要说明“Google 日历连接无响应，30 秒后自动重试”。
结论“可预测性、可靠性和可理解性，就是 Agent 产品本身”。

右侧大纲保持同一课程结构，高亮第 3、4 节；不显示课程页脚。
```

## 第三张：模态匹配与完整路径

```text
尾段从第 5 节“产品模态与用户意图的匹配”开始。

首个对照“聊天不是所有 AI 能力的天然归宿”：输入端是文本框的语言屏障，输出端是长文本的认知成本；结论“界面适应人，而不是人适应界面”。

5.1 输入与输出模态：
输入包括点按、语音、自然语言、表单/向导、GUI、多模态；
输出包括推送通知、音频摘要、短文本、视觉仪表盘、交互画布、行内确认；
提示“模态选择要增加信息路径，同时提供无障碍替代”。

5.2 任务审计：输入约束、输出约束、社交约束、认知负荷；证据路径为“情境观察 → 聚焦访谈 → 协作工作坊”。

5.3 输入/输出对齐矩阵：覆盖快速状态检查、具体细节查询、复杂分析、创意生成、监控/警报、引导式任务六类用户意图。

5.4 野外技术员的多模态交接：高空作业现场的厚手套、强眩光和手忙眼忙，使用语音输入与简短音频摘要；回到卡车后交接给 15 英寸视觉仪表盘，查看历史趋势、电网地图并深度复核。仅使用文案里的案例数据“诊断时间缩短 20%”。

结语绘制五层路径：原则层、模式层、时机层、呈现层、形态层；最终强调“自主性是技术系统的输出，可信度是设计过程的输出”。

页脚：本课产出“一份 Agent 人机协作设计清单：原则、信任模式、透明性时刻、状态反馈与模态选择”，按钮“进入下一课 →”。右侧大纲高亮第 5 节，继续学习指向“下一课：建立可观测性”。
```
