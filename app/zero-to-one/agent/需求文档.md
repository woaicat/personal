# 「从 0 到 1 设计一个 Agent」需求文档

## 1. 项目定位

- 所属系列：从 0 到 1 设计一个东西
- 首个专题：从 0 到 1 设计一个 Agent
- 内容形式：以连续课程引导用户完成一套 Agent 方案，而不是提供彼此独立的知识文章
- 教学案例：为淘宝商家设计一个电商客服 Agent。该案例仅用于教学，不代表淘宝官方需求或真实系统
- 目标用户：准备设计 Agent 的产品经理、AI 产品新人，以及需要补齐产品与工程协作方法的从业者
- 最终产出：一份完整的“电商客服 Agent 设计方案包”，包括需求判断、架构、提示词、工具与上下文方案、评测方案和监控方案

## 2. 产品目标与第一版边界

### 产品目标

1. 用一个虚拟案例串起 Agent 从需求调研到上线监控的全过程。
2. 每一课只解决一个关键问题，并把结论累积到最终方案中。
3. 让用户理解模型、提示词、Agent Loop、工具、MCP、Skill、上下文、记忆、多智能体、安全、成本、评测和可观测性之间的关系。
4. 让用户完成课程后，能够独立输出一份可评审、可验证的 Agent 设计方案。

### 第一版不做

- 不接入真实淘宝数据、接口或账号。
- 不在课程网站内运行真实 Agent、MCP Server 或沙箱代码。
- 不提供登录、云端同步、付费、评论或后台内容管理。
- 不照搬参考网站的品牌、文案和插画，只借鉴课程组织与阅读交互。

## 3. 信息架构

第一版只有两个核心页面：

| 页面 | 建议路由 | 作用 |
| --- | --- | --- |
| 课程列表页 | `/zero-to-one/agent` | 说明课程价值、展示阶段与章节、记录进度并继续学习 |
| 课程详情页 | `/zero-to-one/agent/[lessonId]` | 使用统一模板承载每一课内容、案例推进和阶段产出 |

后续其他“从 0 到 1”专题可以继续放在 `app/zero-to-one/` 下，按专题建立独立目录。

## 4. 页面结构

### 4.1 课程列表页

1. 顶部导航
   - 返回个人作品集或系列首页。
   - 显示专题名称“从 0 到 1 设计一个 Agent”。

2. 课程头图区
   - 课程标题和一句话说明。
   - “开始学习”或“继续学习”按钮。
   - 已完成章节数和总体进度。
   - 简要说明最终会得到什么。

3. 阶段与章节列表
   - 按“需求调研、设计智能体、评测智能体、监控智能体”分组。
   - 每张章节卡片展示编号、标题、摘要、案例任务和学习状态。
   - 状态分为“未开始、学习中、已完成”。
   - 点击卡片进入对应详情页。

4. 课程说明
   - 明确课程使用虚拟案例。
   - 提示课程内容不等于真实淘宝系统方案，涉及模型和工具时应以实施时的实际能力为准。

### 4.2 课程详情页（通用模板）

1. 顶部区
   - 返回课程目录。
   - 显示“第 X 课 / 共 14 课”、所属阶段、标题和本课目标。

2. 正文区
   - 为什么要做：解释本课解决的问题。
   - 核心知识：用短段落、流程图、对比卡和示例讲解概念。
   - 案例推进：把知识应用到电商客服 Agent。
   - 决策与边界：明确本课确定了什么、暂时不做什么。
   - 本课产出：形成一张可复用的方案卡或清单。

3. 本章目录
   - 桌面端固定在正文右侧，展示当前章节锚点。
   - 随滚动高亮当前位置；点击后滚动到对应内容。
   - 移动端收起为可展开目录。

4. 术语解释
   - 对 Agent Loop、MCP、Skill、Hook、Sandbox 等术语提供原位解释。
   - 点击术语后显示简短定义、使用场景和案例中的对应关系，不跳离课程。

5. 章节收束
   - 本课总结。
   - “到目前为止，我们已经确定了”累计结论。
   - “标记完成”按钮。
   - 上一课、下一课导航。

## 6. 案例主线

虚拟案例围绕淘宝商家的售前与售后客服展开：

- 用户：消费者、客服人员、客服主管、商家运营。
- 典型任务：商品咨询、订单查询、物流解释、退换货判断、优惠规则解释和复杂问题转人工。
- Agent 可使用的示例能力：查询商品知识、读取订单状态、检索平台规则、生成回复和发起转人工。
- 关键边界：不能擅自退款、修改订单、承诺未确认权益或泄露其他用户信息。
- 最终目标：在保证正确性与安全性的前提下，提高常见问题解决率，缩短响应时间，并让人工客服接管高风险或复杂问题。

每一课都要沿用同一批角色、流程和约束，不能为了讲新概念随意增加未经说明的能力。

## 7. 核心交互与业务功能

### 学习进度

- 用户首次进入章节时，状态从“未开始”变为“学习中”。
- 用户在章节底部点击“标记完成”后，状态变为“已完成”。
- 列表页“继续学习”进入最近阅读但未完成的章节；没有记录时进入第 1 课。
- 第一版使用浏览器本地存储记录章节状态、最近章节和阅读位置。

### 内容阅读

- 支持章节目录锚点跳转和滚动高亮。
- 支持术语原位解释。
- 支持流程图、架构图、对比卡、方案清单和示例对话等内容模块。
- 支持上一课、下一课连续阅读。

### 案例与产出

- 每课至少包含一个“应用到电商客服 Agent”的案例区块。
- 每课展示明确产出，并在章节底部累积已确认结论。
- 最后一课汇总前 13 课的关键结论，形成完整设计方案，不增加新的产品能力。

### 响应式与可用性

- 桌面端正文与本章目录双栏展示；移动端改为单栏。
- 移动端不能出现整页横向滚动，目录、流程图和宽表格应可折叠或局部滚动。
- 按钮、链接和章节卡片具备悬停、键盘聚焦、按下和禁用状态。
- 正文、状态和导航不能只依赖颜色表达含义。

## 8. 视觉方向

- 整体保持白底、大留白、黑灰正文和单一强调色。
- 列表页使用大尺寸横向章节卡片；详情页以长文阅读为主。
- 重要流程尽量使用图解或卡片，不连续堆叠大段文字。
- 可以为案例设计独立角色和插画，但不得直接复制参考网站人物或品牌素材。
- 与个人作品集保持入口关系，但课程内部可以有独立的视觉识别。

## 9. 内容和开发组织建议

```text
app/zero-to-one/
└── agent/
    ├── 需求文档.md
    ├── page.tsx                 # 后续：课程列表页
    ├── [lessonId]/page.tsx      # 后续：通用课程详情页
    ├── _components/             # 后续：仅供本专题使用的组件
    ├── _content/                # 后续：章节元数据与正文
    └── _assets/                 # 后续：插图、流程图等物料
```

第一版优先让课程内容与页面模板解耦：章节标题、摘要、阶段、状态和正文模块由内容数据驱动，详情页只维护一套页面结构。

## 10. 第一版验收标准

1. 课程列表页能够展示 4 个阶段和 14 个章节。
2. 任意章节卡片都能进入使用统一模板的详情页。
3. 进度、继续学习、标记完成和上一课/下一课逻辑可用。
4. 详情页包含正文、本章目录、术语解释、案例区块、本课产出和累计结论。
5. 桌面端和移动端主要阅读路径均可使用，页面无整页横向溢出。
6. 所有章节持续使用同一个虚拟案例，并明确区分已确认设计与教学假设。
7. 第一版不依赖登录、后端数据库或真实 Agent 接口即可完整浏览。
